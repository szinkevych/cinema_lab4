# API та резервне копіювання

## API v1

API доступне без входу лише для читання та не повертає персональних даних.
Усі відповіді мають формат JSON. Максимальний розмір сторінки — 100 записів.

| Метод і шлях | Призначення | Параметри |
|---|---|---|
| `GET /api/v1/movies` | Каталог фільмів і жанрів | `q` — пошук за назвою, `limit` — 1–100 (типово 50) |
| `GET /api/v1/screenings` | Розклад із доступністю місць | `movie_id`, `from`, `to` (формат `YYYY-MM-DD`), `limit` |
| `GET /api/v1/screenings/<id>/availability` | Дані про сеанс і кількість вільних місць | Ідентифікатор сеансу в URL |

Приклади:

```text
http://127.0.0.1:5000/api/v1/movies?q=дюна
http://127.0.0.1:5000/api/v1/screenings?from=2026-10-24&to=2026-10-31
http://127.0.0.1:5000/api/v1/screenings/1/availability
```

Помилки повертаються JSON-об'єктом `error` з полями `code` та `message`.

## Резервна копія

Із кореня репозиторію виконайте:

```powershell
python database\backup.py
```

Скрипт створює файл `backups\cinema_<UTC-дата-час>.dump` у custom-форматі
PostgreSQL. Спочатку використовується `pg_dump`, якщо він доступний у `PATH`;
інакше команда запускає `pg_dump` у сервісі `postgres` через Docker Compose.
Для запасного варіанта потрібні Docker CLI та запущений контейнер. Для системного
`pg_dump` стандартні змінні середовища `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`
та `PGPASSWORD` перевизначають параметри підключення. Docker-варіант підключається
до локальної бази контейнера `postgres`; у ньому використовуються `PGDATABASE` і
`PGUSER`, а хост і порт задаються конфігурацією Compose.

Відновлення в порожню базу (команда видаляє об'єкти у цільовій базі, тому
перевірте назву бази перед запуском):

```powershell
pg_restore --no-owner --clean --if-exists --dbname=cinema --host=localhost --port=5434 --username=postgres backups\cinema_<UTC-дата-час>.dump
```

За потреби перед `pg_restore` задайте `PGPASSWORD` у середовищі поточного
термінала. Резервні файли не слід додавати до Git.

## Звіт Excel

Адміністратор може завантажити зведений звіт на сторінці «Звіти» кнопкою
«Завантажити Excel» або «Завантажити PDF». XLSX містить огляд, виручку за залами
й фільмами та денну виручку; для залів і днів продажів додаються вбудовані
діаграми. PDF містить ті самі зведені таблиці й показники та підтримує українські
символи за наявності системного шрифту Arial або DejaVu Sans. Обраний період
застосовується до звіту за залами, а інші розрізи показують усю історію продажів.

## SQL-процедури та журнал змін

Під час ініціалізації БД виконується `database/07_level3_completions.sql`
після попередніх SQL-файлів. Він додає процедури `sell_ticket_proc`,
`cancel_ticket_proc` і `hall_revenue_report_proc`, а також аудит змін у таблицях
жанрів, залів та місць. У застосунку процедури продажу, скасування й звіту
використовуються напряму. Пошук за підрядком прискорюють індекси `pg_trgm`.
Для вже створеної Docker-бази одноразово застосуйте
міграцію з кореня репозиторію:

```powershell
Get-Content database\07_level3_completions.sql -Raw |
    docker compose exec -T postgres psql -U postgres -d cinema
```
